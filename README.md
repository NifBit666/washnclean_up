## วิธีเปิดใช้งาน

แนะนำให้รันผ่านเซิร์ฟเวอร์เล็กๆ แทนการดับเบิลคลิกเปิดไฟล์ตรงๆ เพื่อให้ localStorage
ทำงานถูกต้องข้ามหน้า:

```bash
cd wash-clean-up
python3 -m http.server 8000
```

แล้วเปิด http://localhost:8000/index.html

## หมายเหตุ

- ยังเป็น front-end prototype เท่านั้น ข้อมูลอยู่ใน localStorage ของเบราว์เซอร์เครื่องนั้น
  ยังไม่เชื่อมฐานข้อมูล/เซิร์ฟเวอร์จริง
- เวลาเดินของเครื่องที่ "ไม่ว่าง" นับสดด้วย JS (ตั้งแต่เวลาที่แอดมินกดเปลี่ยนสถานะ)
- ฟอนต์ (Baloo 2 / IBM Plex Sans Thai) โหลดจาก Google Fonts ต้องต่ออินเทอร์เน็ตตอนเปิดหน้าเว็บ
  ถ้าออฟไลน์จะ fallback ไปฟอนต์ระบบแทน

## บันทึกการแก้ไข (รอบแก้บัค + รองรับหลายหน้าจอ)

### บัคที่แก้แล้ว

1. **หน้า Admin Login รีโหลดวนไม่รู้จบ** — `admin/script.js` ถูกโหลดทั้งใน `login.html`
   และ `dashboard.html` แต่โค้ดสั่ง redirect ไป `login.html` ทันทีเมื่อไม่พบ session
   ทำให้หน้า login สั่ง redirect ใส่ตัวเองซ้ำไม่จบ แก้โดยแยกเงื่อนไขว่าโค้ดส่วนไหน
   ควรรันในหน้าไหน (เช็กจาก element เฉพาะของแต่ละหน้า)

2. **ฟอร์ม Login ไม่ทำงาน** — ไม่มี handler ตรวจ username/password อยู่เลย
   เพิ่มให้แล้ว พร้อม toast แจ้งเตือนเมื่อรหัสผิด และสถานะกำลังโหลดตอนกดเข้าสู่ระบบ

3. **หน้า Login ไม่มี CSS** — `login.html` เรียกใช้คลาส `login-wrapper`, `login-card`,
   `hero-art`, `drum`, `bubble` ฯลฯ ที่ไม่มีอยู่ใน `admin/style.css` เลย
   เขียนสไตล์เพิ่มโดยยึดโทนเดิม (ฟ้า–กรมท่า) และใส่อนิเมชันเครื่องซักผ้าแบบหน้าแรก

4. **Toast ไม่แสดงผลทั้งระบบ** — `showToast()` หา `#toast-container` ไม่เจอใน
   `dashboard.html` แล้ว return เงียบๆ ทำให้ข้อความ "บันทึกสำเร็จ / เพิ่มเครื่องสำเร็จ /
   ลบสำเร็จ" ไม่เคยขึ้น เพิ่ม container ที่ขาดแล้ว

5. **หน้ารายรับแสดงผลไม่ครบ** — สคริปต์เขียนค่าลง `#rev-washer-count` และ
   `#rev-iron-count` ที่ไม่มีอยู่จริงใน HTML ทำให้เกิด error กลางฟังก์ชัน
   โค้ดบรรทัดถัดไปจึงไม่ทำงาน ผลคือ **เตารีดแสดง ฿0 ตลอด** และ
   **รายการรายได้แยกตามเครื่องว่างเปล่า** แก้โดยเพิ่ม element ที่ขาด
   และเปลี่ยนไปใช้ helper `setText()` เพื่อไม่ให้ element ที่หายไปทำทั้งหน้าพังอีก

6. **CSS keyframe เขียนผิดไวยากรณ์** — `transform: translateY(0); scale(1);`
   ใน `@keyframes popUp` ไม่ถูกต้อง เบราว์เซอร์ทิ้งค่านั้น แก้เป็น
   `transform: translateY(0) scale(1);`

### การรองรับหน้าจอ (มือถือ + คอมพิวเตอร์)

ยึดสไตล์เดิมทั้งหมด **หน้าจอต่ำกว่า 768px แสดงผลเหมือนเดิมทุกจุด**
เพิ่มเฉพาะ breakpoint สำหรับจอใหญ่ขึ้น:

- ขยายความกว้างเนื้อหาตามขนาดจอ (460–480px → 720–760px → 1040–1080px)
  ไม่ให้เนื้อหาถูกบีบเป็นแถบแคบกลางจอคอม
- เพิ่มจำนวนคอลัมน์การ์ด: ฝั่งนักศึกษา 2 → 4 → 5, ฝั่งแอดมิน 2 → 3 → 4
- **ปุ่ม + (FAB)** เดิมยึดขอบขวาของจอ ทำให้ลอยห่างจากเนื้อหามากบนจอคอม
  เปลี่ยนเป็นยึดกับขอบขวาของกล่องเนื้อหาแทน
- หน้ารายรับและหน้าแจ้งซ่อมจัดเป็น 2–3 คอลัมน์บนจอใหญ่
- เว้นระยะล่างของฟอร์มแจ้งปัญหาเพิ่ม กันปุ่ม "ส่งรายงาน" ถูกแถบเมนูล่างบัง
- รองรับมือถือจอเล็กมาก (≤360px) และจอเตี้ย
- ใช้ `100dvh` กันแถบ URL ของเบราว์เซอร์มือถือบังเนื้อหา
- เปิดเอฟเฟกต์ hover เฉพาะอุปกรณ์ที่ใช้เมาส์ (`@media (hover: hover)`)
  เพื่อไม่ให้มือถือแตะแล้วเอฟเฟกต์ค้าง
- รองรับ `prefers-reduced-motion` สำหรับผู้ใช้ที่ตั้งค่าลดการเคลื่อนไหว

### ผลการทดสอบ

ทดสอบด้วยเบราว์เซอร์จริง (headless Chromium) ที่ความกว้าง 320 / 390 / 834 / 1440px
ครบทุกหน้าและทุก modal: **ไม่พบ JavaScript error และไม่มีการล้นแนวนอน**
ฟังก์ชันฝั่งแอดมิน (เพิ่ม / แก้ไข / เปลี่ยนสถานะ / ลบเครื่อง / จัดการใบแจ้งซ่อม)
และฝั่งนักศึกษา (ดูเครื่อง / เปิดรายละเอียด / ส่งรายงาน / ระบบคูลดาวน์) ทำงานครบถ้วน

## บันทึกการแก้ไข (รอบแก้หน้ารายรับ)

ธีม สี ฟอนต์ และเลย์เอาต์เหมือนเดิมทุกอย่าง เทียบภาพก่อน/หลังแล้ว
จุดที่ต่างมีแค่ช่องเตารีดที่เปลี่ยนจาก "-" เป็น "ฟรี" (ให้ตรงกับรายการด้านล่าง)

### ต้นเหตุหลัก
ตัวเลขรายรับเดิม **ไม่ได้มาจากการใช้งานจริง** แต่คำนวณจากเลขชื่อเครื่อง
(`ใช้งาน = เลขเครื่อง × 3 + เลขเครื่อง % 5`) แล้วเก็บไว้ในตัวแปรชั่วคราว ทำให้เกิดบัคต่อเนื่องหลายข้อ
แก้โดยเพิ่ม "ประวัติการใช้งาน" (`wcu:usage` ใน localStorage) บันทึกทุกครั้งที่มีการใช้งานจริง
พร้อมราคา ณ ตอนนั้น หน้ารายรับรวมยอดจากประวัตินี้

### บัคที่แก้แล้ว
1. **เพิ่มเครื่องใหม่แล้วมีรายรับทันที** เช่น เครื่อง 7 ที่ยังไม่เคยใช้ขึ้น "ใช้งาน 23 ครั้ง ฿460" → ตอนนี้เริ่มที่ 0
2. **แก้ราคาแล้วรายรับย้อนหลังเปลี่ยนตาม** (20→30 บาท ทำให้ ฿80 กลายเป็น ฿120) → ราคาใหม่มีผลกับครั้งถัดไปเท่านั้น
3. **เปลี่ยนเลขเครื่องแล้วประวัติเปลี่ยน** (เปลี่ยนเครื่อง 1 เป็น 9 แล้วรีเฟรช กลายเป็น "31 ครั้ง ฿930") → ประวัติผูกกับเครื่อง ไม่ผูกกับชื่อ
4. **หยอดเหรียญจริงในหน้า demo แล้วรายรับไม่ขึ้นเลย** → บันทึกทุกครั้งที่จ่ายครบ ส่วนเตารีดนับจำนวนครั้งตอนเสียบปลั๊ก (ฟรี ไม่คิดเงิน)
5. **หน้ารายรับไม่อัปเดตเอง** ต้องกดสลับแท็บใหม่ → อัปเดตภายใน 1 วินาทีเมื่อมีการใช้งานใหม่ และวาดใหม่เฉพาะตอนข้อมูลเปลี่ยน
6. **ลบเครื่องแล้วเงินที่เก็บได้หายไปจากยอดรวม** → ยอดยังอยู่ และแสดงแถว "ลบออกจากระบบแล้ว"
7. **ใส่ราคาติดลบได้** จนรายรับขึ้น "฿-800" → ฟอร์มกันไว้ (`min="0"`) และโค้ดบังคับไม่ให้ต่ำกว่า 0 อีกชั้น
8. **ตั้งราคา 0 บาทแล้วเปิดใหม่เด้งเป็น 20** (ใช้ `||` แทน `??`) ถ้ากดบันทึกซ้ำจะกลายเป็น 20 จริง → แก้แล้ว
9. **หน้า demo ใช้ราคาเก่า** หลังแอดมินแก้ราคา (ราคาฝังไว้ในปุ่มตอนโหลดหน้า) → อ่านราคาล่าสุดทุกครั้งที่หยอดเหรียญ
10. **มีตัว "<" โผล่มุมซ้ายบนทุกหน้าของแดชบอร์ด** และดันเนื้อหาลง 18px ต้นเหตุคือพิมพ์ `<<link` เกินมาหนึ่งตัวใน `dashboard.html`
11. **รายการ "ยังไม่มีข้อมูล" ไม่มีสไตล์** (คลาส `.empty-state` มีแค่ฝั่งนักศึกษา) → เพิ่มในสไตล์แอดมิน
12. **ช่องเตารีดแสดง "-"** ขณะที่รายการด้านล่างเขียน "ฟรี" → ใช้ "ฟรี" ให้ตรงกัน
13. **เครื่องที่เพิ่มใหม่ไปต่อท้ายหลังเตารีด** และเรียงเลขแบบตัวอักษร (10 มาก่อน 2) → จัดกลุ่มเครื่องซักก่อนเตารีด และเรียงเลขแบบตัวเลข
14. **ตัวเลขเงินขึ้นกับภาษาของเบราว์เซอร์** (บางเครื่องแสดง 2.320) → บังคับรูปแบบ ฿2,320
15. **ชื่อเครื่องที่มี `<...>` ถูกแปลงเป็น HTML** → แสดงเป็นข้อความธรรมดา
16. **ตัวเลขยาวดันกล่องล้นจอมือถือ** → กันล้นโดยไม่เปลี่ยนขนาดหรือสี
17. **"รายรับสะสม" ในหน้าตั้งค่าเครื่อง** ใช้ตัวเลขปลอมชุดเดียวกัน → ดึงจากประวัติจริง และอัปเดตสดขณะเปิดอยู่

### ข้อมูลตัวอย่าง
ครั้งแรกที่เปิด ระบบสร้างประวัติตัวอย่างด้วยสูตรเดิม หน้ารายรับจึงเริ่มที่ **฿2,320** เหมือนเดิม
ต่อจากนั้นยอดเพิ่มตามการใช้งานจริงและไม่รีเซ็ตตอนรีเฟรช
ถ้าอยากเริ่มนับจาก 0 ให้พิมพ์ใน Console ว่า `localStorage.setItem("wcu:usage", "[]")`
(ถ้าจะล้างรายจ่ายตัวอย่างด้วย ให้พิมพ์ `localStorage.setItem("wcu:expenses", "[]")` เพิ่ม)

`shared-data.js`, `admin/script_ad.js`, `admin/dashboard.html`, `admin/style.css`, `demo/index.html`

## บันทึกการเพิ่มฟีเจอร์ (หน้ารายรับแบบละเอียด + หน้ารายจ่าย)

ใช้สี ฟอนต์ มุมโค้ง และเงาชุดเดิมของธีมทั้งหมด การ์ดใหม่ทุกใบสร้างจากสไตล์ที่มีอยู่แล้ว
สีในกราฟเป็นเฉดเข้มขึ้นของสีในธีม (ฟ้า / เหลือง / ชมพู / กรมท่า)
และผ่านการตรวจความต่างของสีสำหรับผู้มีภาวะตาบอดสีแล้ว

### ตัวเลือกช่วงเวลา (ใช้ร่วมกันทั้งสองหน้า)
**วันนี้ / 7 วัน / 30 วัน / ทั้งหมด** ทุกตัวเลข กราฟ และรายการในหน้าจะคำนวณตามช่วงที่เลือก
และเทียบกับช่วงก่อนหน้าที่ยาวเท่ากันให้อัตโนมัติ (▲/▼ เป็น %)

### หน้ารายรับ
- **ยอดรวม** ของช่วงที่เลือก พร้อมเทียบกับช่วงก่อนหน้า
- **ตัวเลขสำคัญ 4 ช่อง:** จำนวนการใช้งาน (ซัก/รีด), รายรับเฉลี่ยต่อรอบซัก, รายรับเฉลี่ยต่อวัน, เครื่องทำรายได้สูงสุด
- **แยกเครื่องซักผ้า / เตารีด** พร้อมจำนวนเครื่องและจำนวนครั้ง
- **กราฟรายรับตามเวลา:** ปรับหน่วยเองตามช่วง (รายชั่วโมง / รายวัน / รายสัปดาห์ / รายเดือน)
  แตะหรือชี้ที่แท่งเพื่อดูตัวเลข และกด "ดูตาราง" ได้
- **กราฟช่วงเวลาที่มีคนใช้งาน:** ไฮไลต์ชั่วโมงที่คนใช้มากสุด + สัดส่วน เช้า/บ่าย/เย็น/ดึก
- **รายได้แยกตามเครื่อง:** จำนวนครั้ง, เฉลี่ยต่อครั้ง, ใช้ล่าสุดเมื่อไร, แถบสัดส่วน %,

### รายรับอ้างอิงจากหน้า demo (Hardware Simulator)

- เหรียญที่หยอดค้างเก็บไว้ในระบบ **รีเฟรชหน้า demo แล้วไม่หาย** (เดิมหาย)

  - สรุป "เงินเข้าระบบวันนี้ / รวมทั้งหมด / รอบซักวันนี้"
  - ตัวเลข +฿10 เด้งตอนหยอด
  - แถบความคืบหน้าเหรียญ และป้ายราคา
  - เวลาถอยหลังขณะซัก
- ปุ่ม **"ข้ามเวลา (ซักเสร็จทันที)"** ไว้เดโมรอบต่อไปได้เลย ไม่ต้องรอ 60 นาที
- หน้ารายรับมีแถบบอกที่มาของเงิน, ลิงก์ **"เปิดหน้า demo ↗"**
  และปุ่ม **"ลบข้อมูลตัวอย่าง"** เพื่อให้เหลือเฉพาะเงินจากหน้า demo

### หน้ารายการแจ้งซ่อม (ออกแบบใหม่ในธีมเดิม)
- **การ์ดสรุป 3 สถานะ:** รอตรวจสอบ / กำลังซ่อม / ซ่อมเสร็จ กดที่การ์ดเพื่อสลับรายการ
- สรุปสั้นๆ เช่น เวลาซ่อมเฉลี่ย, อาการที่เจอบ่อยสุด, ใบที่ยังไม่ระบุเครื่อง
- ตัวกรอง: ทั้งหมด / เครื่องซักผ้า / เตารีด / ยังไม่ระบุเครื่อง
- **การ์ดใหม่:**
  - ไอคอนเครื่องและชื่อเครื่อง
  - ป้ายสถานะ (มีไอคอนกำกับ)
  - ชิปอาการ, รายละเอียด และรูปย่อ
  - รหัสนิสิตผู้แจ้ง และระยะเวลาที่รอ (เกิน 1 วันขึ้นตัวแดง)
  - ปุ่มลัด "เริ่มซ่อม" / "ซ่อมเสร็จ"
- **หน้าต่างรายละเอียด (แตะการ์ด):**
  - รูปหลักฐานขนาดใหญ่ แตะเพื่อซูม
  - ข้อมูลผู้แจ้ง, เวลาแจ้ง, สถานะเครื่องตอนนี้
  - อาการ และรายละเอียดจากผู้แจ้ง
  - ไทม์ไลน์ แจ้งเข้ามา → เริ่มซ่อม → ซ่อมเสร็จ
- **แอดมินระบุข้อมูลได้:**
  - **เครื่องที่มีปัญหา** (ใบที่ไม่รู้ว่าเครื่องไหนก็ระบุได้ หรือย้ายไปเครื่องอื่นได้)
  - **สถานะ**
  - **บันทึกของแอดมิน** (สาเหตุ / วิธีแก้)
  - **ค่าซ่อม** บันทึก/แก้/ลบในหน้ารายจ่ายให้อัตโนมัติ ไม่มีรายการซ้ำ
- สถานะเครื่องเปลี่ยนตามใบแจ้งให้เอง:
  - เริ่มซ่อม → เครื่องขึ้น "มีปัญหา"
  - ซ่อมเสร็จ → เครื่องเปิดใช้งาน
  - ย้ายใบแจ้งไปเครื่องอื่น → เครื่องเดิมเปิดใช้งานคืน
- ใบแจ้งใหม่จากนักศึกษาโผล่เองโดยไม่ต้องรีเฟรช
- ปุ่ม "ดูเครื่องนี้" กระโดดไปหน้าตั้งค่าเครื่อง
- ลบใบแจ้งซ่อมด้วยหน้าต่างยืนยันแบบเดียวกับธีม (เดิมใช้กล่อง confirm ของเบราว์เซอร์)

### บัคที่แก้เพิ่ม
1. **หน้าตั้งค่าเครื่องดึงใบแจ้งซ่อมผิดเครื่อง** — เดิมจับคู่จากชื่อหมวด ("เครื่องซักผ้า")
   เครื่องไหนเสียก็ไปดึงใบแจ้งของเครื่องอื่นมาแสดง และถ้าใบเก่าไม่มี `detail` หน้าจะ error
   → ตอนนี้จับคู่ด้วยรหัสเครื่องเท่านั้น
2. **กด "ซ่อมเสร็จแล้ว (เปิดใช้งาน)" ที่เครื่อง แต่ใบแจ้งซ่อมยังค้าง "รอดำเนินการ"** → ปิดใบแจ้งให้ด้วย
3. **ตอนกดซ่อมเสร็จ ระบบเดาเครื่องจากเลขในชื่อ** เช่นใบของเตารีด 4 ไปเปิดเครื่องซักผ้า 4 → แก้แล้ว
4. **เพิ่ม/แก้ไขเตารีดไม่ได้เลย** — ช่อง "เวลาทำงาน" ที่ซ่อนไว้มีค่า 0 แต่ตั้ง `min="1"`
   เบราว์เซอร์จึงไม่ยอมส่งฟอร์ม
5. **"ปิดการใช้งาน (พักเครื่อง)" ไม่ได้ปิดจริง** แต่ทำให้เครื่องขึ้น "กำลังใช้งาน" 60 นาที
   → ตอนนี้ปิดใช้งานจริง และมีปุ่ม "เปิดใช้งานเครื่อง"
6. **ตั้งหมายเลขเครื่องซ้ำได้** (เช่นเครื่องซักผ้า 2 สองเครื่อง) → กันไว้ทั้งตอนเพิ่มและแก้
   และเลขที่ระบบแนะนำตอนเพิ่มเครื่องไม่ชนเลขเดิมหลังลบเครื่องแล้ว
7. **หน้า demo ชื่อเครื่องไม่อัปเดต** หลังแอดมินเปลี่ยนเลข (เดิมเช็กแค่จำนวนเครื่อง)
8. **หน้า demo เครื่องค้าง "กำลังทำงาน"** ถ้าไม่ได้เปิดหน้าแอดมิน/นักศึกษาไว้ → ครบเวลาแล้วกลับมาว่างเอง
9. **เครื่องที่มีใบแจ้งซ่อมค้าง ซักเสร็จแล้วกลับเป็น "ว่าง"** → กลับเป็น "มีปัญหา" ตามใบแจ้ง
10. **รูปแจ้งซ่อมทำพื้นที่เก็บข้อมูลเต็มแล้วส่งไม่สำเร็จแบบเงียบๆ** → ลดขนาดรูปแล้วส่งใหม่อัตโนมัติ
    ถ้ายังไม่ได้จะแจ้งข้อความให้รู้
11. **ข้อมูลใน localStorage เสียแล้วทั้งเว็บพัง** → อ่านไม่ได้จะใช้ค่าว่างแทน
12. หน้า Login: แก้คำผิด "รหัผ่าน" และเพิ่มไอคอนบนแท็บ
13. ใบแจ้งซ่อมตัวอย่างชุดเก่า (ลงวันที่ มิ.ย. ไม่มีข้อมูลเครื่อง จึงขึ้น "รอมาแล้ว 115 วัน")
    เปลี่ยนเป็นชุดใหม่ที่สมจริงกว่า
    แทนเฉพาะใบตัวอย่างที่ยังไม่มีใครแก้ ใบจริงไม่ถูกแตะ

## ขึ้นเว็บจริง: Firebase (ฐานข้อมูล) + Vercel (โฮสต์)

### เลือกใช้อะไร และเพราะอะไร
| ส่วน | ที่เลือก | เหตุผล |
|---|---|---|
| ฐานข้อมูล | **Firebase Realtime Database** | สถานะเครื่องต้องอัปเดตทันทีทุกเครื่อง (หยอดเหรียญหน้า demo → นิสิตเห็นทันที) ซึ่งเป็นจุดเด่นของ Realtime Database · โครงสร้าง JSON ตรงกับข้อมูลเดิม · ใช้ฟรี (Spark) · ต่อ ESP32/บอร์ดจริงผ่าน REST API ได้ในอนาคต |
| ล็อกอิน | **Firebase Authentication** | แอดมินใช้ Email/Password (รหัสไม่ต้องเก็บในโค้ดอีก) · นิสิตและหน้า demo ใช้ Anonymous (ไม่ต้องสมัคร แต่ยังคุมสิทธิ์ได้) |
| รูปหลักฐาน | เก็บใน Realtime Database (ย่อรูปก่อนส่ง) | Cloud Storage ของ Firebase ต้องใช้แพ็กเกจเสียเงิน (Blaze) จึงไม่ใช้ |
| โฮสต์ | **Vercel** | เว็บนี้เป็นไฟล์ static ล้วน ขึ้น Vercel ได้ทันทีโดยไม่ต้อง build |

### สิทธิ์การใช้งาน (database.rules.json)
- **แอดมิน** (อีเมลใน rules) อ่าน/แก้ได้ทุกอย่าง
- **นิสิต**
  - เห็นสถานะเครื่อง และส่งใบแจ้งซ่อมได้
  - เห็นเฉพาะใบแจ้งของตัวเอง (ของคนอื่นที่มีเบอร์โทรจะไม่เห็น)
  - เปลี่ยนได้แค่สถานะเครื่อง แก้ราคาหรือลบเครื่องไม่ได้
- **หน้า demo** บันทึกการหยอดเหรียญและสถานะเครื่องได้ แต่ลบรายรับไม่ได้
- รายจ่ายทั้งหมดเห็นได้เฉพาะแอดมิน
- รหัสผ่านไม่ถูกเก็บในฐานข้อมูล (rules ห้ามไว้)

### ขั้นตอนตั้งค่า Firebase (ครั้งเดียว)
1. https://console.firebase.google.com → **Create a project**
2. **Build → Realtime Database → Create Database**
   - เลือก location **Singapore (asia-southeast1)**
   - เลือก **Start in locked mode**
3. แท็บ **Rules** → ลบของเดิม แล้ววางเนื้อหาไฟล์ `database.rules.json` → **Publish**
4. **Build → Authentication → Get started**
   - เปิด **Email/Password** และ **Anonymous**
   - แท็บ **Users → Add user** → อีเมล `admin@washnclean.app` + รหัสผ่านที่ต้องการ (อย่างน้อย 6 ตัว)
5. **Authentication → Settings → User actions** → เอาติ๊ก **Enable create (sign-up)** ออก (กันคนนอกสมัครเอง)
6. ⚙️ **Project settings → General → Your apps → `</>`** เพิ่มเว็บแอป
   - คัดลอก `firebaseConfig` มาวางใน `firebase-config.js` แทน `null`
   - ต้องมีบรรทัด `databaseURL`
7. ถ้าอยากใช้อีเมลแอดมินอื่น ต้องแก้ 2 ที่ให้ตรงกัน: `WCU_ADMIN_EMAILS` ใน `firebase-config.js` และทุกบรรทัด `admin@washnclean.app` ใน `database.rules.json`

แอดมินเข้าสู่ระบบครั้งแรก ระบบจะสร้างข้อมูลตั้งต้นให้เอง ได้แก่ เครื่อง 10 เครื่อง ใบแจ้งตัวอย่าง รายรับ และรายจ่ายตัวอย่าง
ข้อมูลตัวอย่างลบได้จากปุ่ม "ลบข้อมูลตัวอย่าง" ในหน้ารายรับ
ในหน้าแอดมินจะมีป้าย **● เชื่อมต่อฐานข้อมูลแล้ว** บอกว่าต่อ Firebase สำเร็จ

### บัคที่แก้
1. หัวข้อด้านบนหน้านิสิตขึ้น "รายการ" ตลอด → ตอนอยู่หน้าฟอร์มเปลี่ยนเป็น "แจ้งปัญหา"
2. ในหน้าฟอร์ม ไอคอนเครื่องซักผ้าที่แถบล่างยังไฮไลต์อยู่ ทำให้ดูเหมือนอยู่หน้ารายการ → เอาไฮไลต์ออก
3. ปุ่ม "โทรหาแอดมินทันที" ในกล่องเตือนอันตรายไม่มีเบอร์ในโหมด Firebase (เบอร์มาถึงหลังโหลดหน้า) → อัปเดตเบอร์ทุกครั้งที่กล่องแสดง และซ่อนปุ่มถ้ายังไม่มีเบอร์
4. "การแจ้งของฉัน" ขึ้น "รอแอดมินดำเนินการ" ทั้งที่แอดมินไม่อนุมัติคืนเงินแล้ว → แสดง "ไม่อนุมัติ"
5. แอดมินแก้เลขเครื่อง การ์ดในหน้านิสิตยังเป็นเลขเดิมจนกว่าจะรีเฟรช → อัปเดตทันที
6. โหมด Firebase ตอนกำลังโหลดขึ้นว่า "ยังไม่มีเครื่องซักผ้าในระบบ" → เปลี่ยนเป็น "กำลังโหลดสถานะเครื่อง…" และถ้าเชื่อมต่อไม่ได้จะบอกให้รีเฟรช
7. ป้ายสถานะในหน้าแอดมินขึ้นว่า "เชื่อมต่อแล้ว" ทั้งที่ยังไม่มีสิทธิ์อ่านข้อมูล (เช่นยังไม่ได้วาง Rules) → ขึ้นสีแดงให้เห็น
8. ช่องค้นหาใบแจ้งซ่อมบนมือถือ ข้อความตัวอย่างยาวจนถูกตัด → ย่อเป็น "ค้นหา…" (เอาเมาส์ชี้จะบอกว่าค้นอะไรได้บ้าง)

## บันทึกการแก้ไขรอบ 7: ตรวจและแก้บัคทั้งระบบ

ตรวจโค้ดทุกหน้า (นิสิต / แอดมิน / demo / หน้าแรก / Firebase) แล้วแก้ตามนี้ ธีมเดิมทั้งหมด

### ความปลอดภัย
1. ข้อความจากผู้ใช้ (เลขเครื่อง, ใบแจ้งซ่อม, รูป) ถูกแทรกเป็นโค้ด HTML ได้ → หนีอักขระครบทุกตัวรวม `"` `'` รับเฉพาะรูปที่เป็นไฟล์ภาพจริง และการแจ้งเตือน (toast) แสดงเป็นข้อความล้วน
2. Rules ของ Firebase เข้มขึ้น
   - คนทั่วไปแก้รายรับที่บันทึกเสร็จแล้วไม่ได้
   - ตรวจชนิดและขนาดข้อมูลทุกช่อง (รูป ข้อความ จำนวนเงิน)
   - ห้ามสร้างเครื่องหรือรายจ่ายที่ข้อมูลไม่ครบ
3. รหัสรายการ (id) สุ่มยาวขึ้น กันชนกันเมื่อหลายเครื่องบันทึกพร้อมกัน

### โหมด Firebase
4. เปิดหน้านิสิตกับหน้าแอดมินในเบราว์เซอร์เดียวกัน รายการแจ้งซ่อมฝั่งแอดมินหายหมด → แยกแคชของแต่ละหน้า
5. นิสิตกดส่งก่อนระบบล็อกอินเสร็จ ใบแจ้งถูกปฏิเสธแล้วหายไป → ใส่เจ้าของใบแจ้งตอนส่งจริง และลองล็อกอินใหม่อัตโนมัติ
6. ขึ้นว่า "ส่งสำเร็จ" ก่อนเซิร์ฟเวอร์ยืนยัน → รอเซิร์ฟเวอร์ตอบก่อน
   - ส่งไม่สำเร็จจะบอกชัด
   - ถ้าเน็ตช้าจะบอกว่าระบบจะส่งให้เองเมื่อเชื่อมต่อได้
7. นับถอยหลังใช้นาฬิกาของเซิร์ฟเวอร์ มือถือที่ตั้งเวลาเพี้ยนจะไม่ทำให้รอบซักของคนอื่นจบก่อนเวลา
8. ออฟไลน์หรือยังโหลดข้อมูลไม่เสร็จ การแก้ไขจะไม่ทับข้อมูลจริง และแอดมินจะเห็นแจ้งเตือนว่ายังไม่ได้บันทึก
9. โหลดไม่เสร็จใน 15 วินาที (เช่น databaseURL ผิด / Rules ไม่อนุญาต) → บอกสาเหตุแทนการขึ้น "กำลังโหลด" ตลอด
10. แอดมิน 2 เครื่องเปิดฐานข้อมูลใหม่พร้อมกัน ข้อมูลตั้งต้นไม่ถูกสร้างซ้ำอีกแล้ว

### การทำงาน
11. นิสิตแจ้งซ่อมเครื่องที่กำลังซักอยู่ รอบของคนที่ใช้อยู่หายทันที → ให้ซักต่อจนจบรอบ แล้วค่อยปิดใช้งานเอง
12. สองกรณีนี้ทำให้เครื่องที่มีใบแจ้งซ่อมค้างกลับเป็น "ว่าง" → ตอนนี้เปลี่ยนเป็น "มีปัญหา"
    - แอดมินกด "หยุดทำงาน"
    - หน้า demo ถอดปลั๊กเตารีด
13. ค่าซ่อมในใบแจ้งกับหน้ารายจ่ายตรงกันสองทาง
    - แก้หรือลบรายจ่ายที่หน้ารายจ่าย ใบแจ้งซ่อมจะอัปเดตตาม (รวมรายการคืนเงิน)
    - กดบันทึกใบแจ้งซ้ำ จะไม่สร้างรายจ่ายซ้ำ
14. ลบข้อมูลตัวอย่างแล้ว "ค่าซ่อมรวม" ยังค้างตัวเลขตัวอย่าง → ล้างให้ด้วย
15. ใบแจ้งที่ข้อมูลเสีย 1 ใบทำให้หน้าแจ้งซ่อมว่างทั้งหน้า → ข้ามใบนั้นได้
16. แก้เลขเครื่องจากอีกเครื่อง/อีกแท็บ การ์ดไม่อัปเดตจนกว่าจะรีเฟรช → อัปเดตทันที (หน้าแอดมินและหน้านิสิต)
17. ลบเครื่องแล้วไม่เตือนว่ามีใบแจ้งซ่อมหรือเหรียญค้าง → เตือนก่อนลบ และกดยกเลิกแล้วกลับไปหน้าต่างเครื่องเดิม
18. เลขเครื่องที่เป็นช่องว่างล้วนบันทึกได้ → ไม่ให้บันทึก และจำกัดความยาวไว้ 10 ตัว
19. ประวัติรายรับใช้เวลาไม่ตรงกัน (เรียงด้วยเวลาหนึ่ง จัดกลุ่มวันด้วยอีกเวลาหนึ่ง) → ใช้เวลาเดียวกันทั้งหมด
20. ไฟล์ CSV
    - ส่งออกช่วงที่ไม่มีข้อมูลแล้วขึ้น "1 รายการ" → นับเฉพาะแถวข้อมูล
    - กันสูตร Excel ได้ครบขึ้น

### หน้าจอและการใช้งาน
21. ดูรูปบนมือถือ แตะเพื่อซูมแล้วเด้งกลับทันที → แตะครั้งเดียวซูมได้
22. ปุ่ม Esc ปิดหน้าต่างได้ทุกหน้า (หน้าต่างยืนยันจะพากลับหน้าต่างเดิมถูกต้อง)
23. ใช้คีย์บอร์ดได้: กด Tab ไปที่การ์ดเครื่องแล้วกด Enter เพื่อเปิด และจะเห็นกรอบสีฟ้าเฉพาะตอนใช้คีย์บอร์ด
24. หน้าต่าง "ส่งรายงานสำเร็จ" บนจอเตี้ยเลื่อนไม่ได้และปิดไม่ได้ → เลื่อนได้แล้ว
25. หน้าต่างเครื่องในหน้านิสิต ปุ่ม "รายงานปัญหา" ไม่อัปเดตตามสถานะจริง → อัปเดตสด
26. ข้อความเตือน "แนบได้สูงสุด 3 รูป" ค้างแม้ลบรูปแล้ว → หายเมื่อแก้ไขรูป
27. ปุ่ม + ในหน้าแอดมินจอ 320px ทับแถบเมนูล่าง → ยกขึ้น
28. หน้า demo
    - พื้นที่เก็บข้อมูลเต็มแล้วปุ่มเงียบไม่ตอบสนอง → แจ้งเตือนให้รู้
    - กด "ข้ามเวลา" ขึ้นว่า "ว่าง" ทั้งที่เครื่องไปเป็น "มีปัญหา" → ข้อความตรงกับสถานะจริง
29. หน้าแรก
    - เครื่องตัวอย่างนับถอยหลังค้างที่ 00:00 → วนใหม่
    - หน้าเกี่ยวกับ error เมื่อลิงก์ #… ขึ้นต้นด้วยตัวเลข
